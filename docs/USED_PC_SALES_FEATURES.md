# 中古PC販売向け機能案

更新日: 2026-11-17

PC診断ツールを、中古PCの検品だけでなく「出品準備・販売判断」にも利用するための機能候補です。

## P0: 優先度 高

### 1. 販売用サマリ

診断ログとは別に、出品担当者がそのまま利用できる `販売用サマリ.txt` または画像を生成する。

掲載候補:

- メーカー / 型番
- CPU
- RAM
- SSD / HDD容量
- GPU
- OS
- Office有無
- バッテリー健康度
- Wi-Fi / Bluetooth
- 画面解像度
- 光学ドライブ
- Webカメラ
- ACアダプタ有無（手入力）
- Windows 11要件の参考判定

販売用ファイルでは以下を原則除外する。

- S/N
- Windows完全プロダクトキー
- UUID
- MACアドレス等の不要な識別情報

### 2. 販売前 要確認フラグ

診断結果から、出品前に確認すべき項目を自動表示する。

例:

- SMART Failure Predictあり
- 代替処理済みセクタ等の注意値
- SSD寿命情報が低い
- バッテリー健康度が低い
- PnPエラーあり
- WHEA / Disk / NTFS等の重大イベントあり
- Windowsライセンス未認証
- TPM / Secure Boot等がWindows 11要件を満たさない可能性
- Office認証状態は未確認

判定は「故障確定」ではなく `要確認` とする。

### 3. 出品用コピペ情報

ChatGPTや販売サイトへ貼り付けやすい、機械可読・人間可読の情報を生成する。

例:

```text
【販売用PC情報】
メーカー:
型番:
CPU:
メモリ:
ストレージ:
GPU:
OS:
Office:
バッテリー:
付属品:
注意事項:
```

## P1: 優先度 中

### 4. ストレージ販売評価

ATA SMART / NVMe情報から以下を整理する。

- 電源投入時間
- 電源投入回数
- 代替処理済みセクタ
- 保留中セクタ
- 訂正不能セクタ
- SSD/NVMe寿命・Percentage Used等（取得可能な場合）

コントローラーやUSB変換等で取得不能な場合は「取得不可」とする。

### 5. バッテリー販売評価

Design CapacityとFull Charge Capacityから健康度を算出し、販売担当者向けの目安表示を追加する。

しきい値は運用ルールとして別途決定する。

例:

- 良好
- 使用感あり
- 劣化大 / 要説明
- 取得不可

自動判定のみで保証可否は決定しない。

### 6. 搭載機能一覧

PnP / WMI等から可能な範囲で以下を確認する。

- Wi-Fi
- Bluetooth
- Webカメラ
- 光学ドライブ
- カードリーダー
- タッチパネル
- 指紋認証
- 有線LAN
- オーディオデバイス

XP / 7では取得精度が異なるためLegacyでは要確認表示を許容する。

### 7. 手動検品チェック

自動取得できない中古品特有の状態を、任意入力で記録する。

- 外装傷
- 液晶傷 / ムラ
- ドット抜け
- キーボードテカリ / 欠損
- タッチパッド
- USB端子
- HDMI / DisplayPort
- スピーカー
- マイク
- カメラ
- ACアダプタ
- バッテリー実使用
- 清掃済み
- 初期化済み

## P2: 将来候補

### 8. 販売価格計算補助

任意入力:

- 仕入原価
- 販売予定価格
- 販売手数料率
- 送料
- 部品交換費

から以下を計算する。

- 粗利
- 粗利率
- 手取り見込
- 損益分岐販売価格

診断機能とは分離した「販売モード」として実装する。

### 9. 出品タイトル案用データ

自動生成例:

```text
DELL Latitude XXXX / Core i5 / 16GB / SSD 512GB / Windows 11
```

タイトル文字数制限に応じた短縮版も用意する。

### 10. 販売ランク補助

ハードウェア状態 + 手動検品結果から社内用ランクの候補を表示する。

例:

- A候補
- B候補
- C候補
- 部品取り候補

最終ランクは人間が確定する。

## 推奨する次の実装

v6.20のXP/7互換性を固めた後、最初に以下を追加する。

1. `販売用サマリ.txt`
2. `販売前_要確認.txt`
3. `出品用情報.txt`

この3点は既存の診断データを再利用できるため、機能追加のリスクが比較的小さく、中古PC販売業務への効果が大きい。
